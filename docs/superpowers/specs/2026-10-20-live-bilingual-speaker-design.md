# 实时中英混合转录与视觉说话人归属设计

日期：2026-10-20

## 目标与范围

在现有 Android 应用中，点击“开始采集”后继续识别画面中的多个人脸，为陌生人分配会话内编号，实时显示中英混合语音的转录内容，并通过说话期间的嘴部动作给文本关联说话人。目标是从发声到界面显示文字和说话人约 2 秒；该数值需要在实际测试中验证，不能作为模型或模拟器的既定性能。允许在运行时将音频流发送到团队控制的远端服务器处理，无需预先上传音频。停止采集时释放摄像头、麦克风和远端会话。

本阶段不实现音色或声纹识别，也不实现多人同时发声的分离。对无法可靠归属的内容保留“未确认说话人”，避免错误归名。保留现有参与者知情同意步骤，以及本地身份库和转录历史。

## 当前基线

应用以 CameraX 取帧，YuNet/SFace 检测、识别和跟踪人脸；未知人使用会话编号。当前画面分析间隔为 900 毫秒。AudioRecord 采集 16 kHz 单声道音频，Vosk 中文小模型产生实时部分结果和最终结果。多人同框时，说话人由用户点选，否则记录为“未确认说话人”。当前模型和代码没有中英混合识别、嘴部动作判断或远端语音服务。

## 方案选择

1. **推荐：端侧视觉归属 + 局域网流式中英识别。** 端侧保留身份跟踪并增加嘴部关键点时间序列；同一音频流发送到团队控制的流式识别服务。以 FunASR 中英文流式模型作为候选，先用样例语句验证同句混合准确率和延迟。现有 Vosk 保留为本地基线和远端不可用时的后备，但后备模式不宣称具备同等中英混合能力。此方案最有希望满足模拟器阶段的延迟目标，也自然形成 Part B 的本地/远端划分实验。
2. **全端侧多语言识别。** 在 Android 上运行多语言模型，减少网络依赖，但模拟器的推理速度、发热和内存开销尚未知。作为后续对照方案，而非第一阶段的默认实现。
3. **双 Vosk 语言模型并行。** 接入成本可能较低，但对一句话中间切换语言没有可靠的仲裁依据，不作为主方案。

## 组件和数据流

- **人脸身份链路**：CameraX 帧 → 现有 YuNet/SFace → FaceTracker → 人脸框、姓名或陌生人编号。身份标签与稳定的 track ID 保持绑定。
- **嘴部活动链路**：对视频帧执行多人脸关键点检测，取得每张脸的嘴部开合与变化量；按画面位置关联到 FaceTracker 的 track ID；将带单调时钟时间戳的活动分数放入短时间窗口。MediaPipe Face Landmarker 是候选，不让它替代现有身份识别，除非实测表明双链路开销不可接受。
- **音频链路**：AudioRecord 的 PCM 数据同时用于输入电平/语音活动检测和语音识别接口。接口支持本地 Vosk 实现与远端流式实现，输出带时间戳的临时转录和最终转录。远端路径使用持续连接发送实时音频块；不得上传既有录音文件作为运行前提。
- **归属与展示**：在有语音活动的时间窗口内，对齐音频与各 track ID 的嘴部活动。某人证据明显领先时，临时转录可显示其标签；证据不足时显示“未确认说话人”。后续帧允许修正临时标签。最终转录写入 SQLite 时，使用该片段的最终标签和时间戳，避免把临时结果反复写入历史。
- **生命周期**：开始后独立启动相机、嘴部分析、音频采集和识别会话；停止或 Activity 暂停时终止它们。远端连接中断时明确显示状态，并可切回现有本地中文识别；不得把失败解释为中英混合识别成功。

## 实时性与可靠性约束

现有每 900 毫秒一帧不足以分析连续嘴部动作。应让身份识别保持较低频率，同时让嘴部活动以更高频率采样，具体帧率由模拟器与真机的实测耗时决定。视觉计算不得阻塞音频采集。对同一段话的临时文字和说话人只更新界面，最终结果才持久化。时钟对齐、跟踪 ID 的稳定性和视频镜像坐标需要在实现时验证。

“2 秒”指从一小段可识别语音结束到界面出现相应文字及说话人标签的目标延迟，同时单独记录首个临时文字延迟。若嘴部归属比文字慢，先显示文字和“判断说话人中”，随后更新标签；不为等待最终转录而冻结界面。演示只安排一人发声，但测试须包含静默、多人可见、嘴部遮挡和识别失败场景。

## 验收与实验

准备固定的中文、英文及句内中英混合语句，记录人工标注文本与真实说话人。对每次测试记录识别文本、字/词错误、首个临时结果延迟、文字及说话人显示延迟、说话人归属正确率、未确认比例、设备和网络条件。先在模拟器上验证功能，再在 Android 真机复核性能。Part B 至少比较现有本地基线与远端流式识别，并解释传输、推理与视觉分析的耗时；进一步的动态划分属于 Part C，待 Part B 数据形成后设计。

## 仍需实测的风险

- 官方模型说明支持中英文和流式输入，但并未证明本项目语句的句内混合准确率或 2 秒延迟；需用固定样本验证。
- 多人脸嘴部关键点检测可能给模拟器带来明显开销；应记录处理帧率与丢帧情况。
- 嘴部活动只能提供视觉证据，不能在遮挡、画外发声或多人同时讲话时保证说话人身份。
- 项目目录当前没有 Git 元数据，设计文档无法在此目录直接提交 commit。
