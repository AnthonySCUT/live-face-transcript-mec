# 人脸流水线：端侧与电脑协同实验

## 模块与连接

```text
CameraX 采集/旋转/缩放（手机）
  -> YuNet 人脸检测
  -> SFace 关键点对齐（112×112）
  -> SFace 特征提取（128 个 float）
  -> 身份库余弦匹配、跨帧跟踪与显示（手机）
                                      -> MediaPipe 嘴部活动与语音文本关联（手机）
```

| 模式 | 手机 | 电脑 | HTTP 上传 |
| --- | --- | --- | --- |
| 本地 | 所有模块 | — | 0 |
| 对齐后卸载 | 采集、检测、对齐、匹配与跟踪 | 特征提取 | 对齐人脸 PNG，经 JSON/Base64 编码 |
| 整帧卸载 | 采集、匹配与跟踪 | 检测、对齐、特征提取 | JPEG 整帧 |
| 动态 | 在上述三个模式之间选择 | 接收对应阶段 | 取决于当前模式 |

电脑端与 Android 使用同一份 YuNet/SFace ONNX 权重；身份库一直保存在手机上。多人脸的对齐图会放在同一请求里；画面无人时也记录请求开销。实际数据大小应从 CSV 的 `upload_bytes` 和 `download_bytes` 读取，整帧经 JPEG、有损压缩，对齐图为无损 PNG，数据量随内容和人数变化。

## 启动电脑服务

在仓库根目录运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt
.\.venv\Scripts\python.exe server\server.py --host 0.0.0.0 --port 8000
```

浏览器访问 `http://127.0.0.1:8000/health` 应返回 `status: ok`。模拟器默认使用 `http://10.0.2.2:8000`；实体手机与电脑连接同一网络，运行 `ipconfig` 查找电脑的 Wi-Fi IPv4，在应用中填写 `http://电脑IPv4:8000`，并按系统提示允许 Python 的局域网访问。调试应用允许内网 HTTP 明文；音频服务沿用 FunASR 原有配置。

## 操作与实验矩阵

1. 启动服务，在应用的“计算切分实验”选择模式、输入最大边长、上行限速与电脑地址。
2. 点击“运行样例切分实验”：自动使用仓库内的样例人脸，覆盖 320/512 像素、无上行限速/512 kbps、三个静态方案及动态方案，写入实验 CSV。此过程可用于检查连通性与实现。
3. 真实视频实验需先获得参与者同意，固定设备、光照、人数和使用时间，分别运行三种静态方案，再运行动态方案；改变尺寸、限速或真实 Wi-Fi/蜂窝连接时记录环境。每种条件重复采样，排除启动预热帧，并分别记录 0/1/2 人等输入规模。
4. 点击“导出实验 CSV”，用系统文件选择器保存；运行 `py -3.12 server\summarize.py 路径\mec-experiments.csv` 生成分组表。原始 CSV 与设备型号、系统、网络、供电情况一起保存。
5. 动态实验改变上行限速或网络，观察界面实际执行位置与 CSV，统计适应前后的耗时。限速选项只控制本应用 HTTP 请求的上行发送速率；真实网络需要另行测量和标注。

## 动态决策

动态模式先分别采样三种方案，再比较指数滑动平均估计：`手机计算耗时 × CPU负载修正 + 电脑计算耗时 + RTT + 上传字节/上行速率 + 下载字节/下行速率`。网络由 64 KiB 上下行探针和一次健康请求每 15 秒测量；手机进程 CPU 时间与经过的时间估算负载。预估更优超过 15% 时切换，每 30 帧重新采样以更新剖析。设置改变后重新采样；动态模式连接电脑失败时回到本地执行。

## 测量解释

- `frame_to_track_ms`：摄像头帧进入分析到身份跟踪完成的时间，包含图像转换、排队、网络探测与计算；样例实验从样例处理开始计时。
- `pipeline_ms`：选择模式后到取得人脸特征的时间；`request_ms` 包含请求、网络和电脑计算，`remote_ms` 是电脑检测/对齐/提取合计，二者存在包含关系。
- `process_cpu_cores`：整个 Android 进程在两次取样之间消耗的 CPU 时间除以经过时间，1.0 约为一个逻辑核运行；包含并行语音和嘴部分析。
- `battery_current_ua`、`battery_charge_uah`、`battery_voltage_mv` 和 `battery_energy_nwh` 为 Android BatteryManager 原始读数；整数最小值表示设备不提供对应指标。电量计可用时，取相同采样区间首末 `battery_energy_nwh` 之差计算能耗；记录电池状态，使用实体机或外部电表，并明确测量区间与单位。
- 初次模型加载、缓存、电脑性能、帧内容与并行负载均会影响结果；报告中保留原始采样与实验条件，以中位数及分位数呈现结果。
