# 人脸流水线：端侧与电脑协同实验

## 模块与连接

```text
CameraX 采集/旋转/缩放（手机）
  -> YuNet 人脸检测
  -> SFace 关键点对齐（112×112）
  -> SFace 特征提取（128 个 float）
  -> 身份库余弦匹配、跨帧跟踪与显示（手机）
                                      -> MediaPipe 嘴部活动与语音文本关联（手机）
```

| 模式 | 手机 | 电脑 | HTTP 上传 |
| --- | --- | --- | --- |
| 本地 | 所有模块 | — | 0 |
| 对齐后卸载 | 采集、检测、对齐、匹配与跟踪 | 特征提取 | 对齐人脸 PNG，经 JSON/Base64 编码 |
| 整帧卸载 | 采集、匹配与跟踪 | 检测、对齐、特征提取 | JPEG 整帧 |
| 动态 | 在上述三个模式之间选择 | 接收对应阶段 | 取决于当前模式 |

电脑端与 Android 使用同一份 YuNet/SFace ONNX 权重；身份库一直保存在手机上。多人脸的对齐图会放在同一请求里；画面无人时也记录请求开销。实际数据大小应从 CSV 的 `upload_bytes` 和 `download_bytes` 读取，整帧经 JPEG、有损压缩，对齐图为无损 PNG，数据量随内容和人数变化。

## 启动电脑服务

在仓库根目录运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt
.\.venv\Scripts\python.exe server\server.py --host 0.0.0.0 --port 8000
```

浏览器访问 `http://127.0.0.1:8000/health` 应返回 `status: ok`。模拟器默认使用 `http://10.0.2.2:8000`；实体手机与电脑连接同一网络，运行 `ipconfig` 查找电脑的 Wi-Fi IPv4，在应用中填写 `http://电脑IPv4:8000`，并按系统提示允许 Python 的局域网访问。调试应用允许内网 HTTP 明文；音频服务沿用 FunASR 原有配置。

## 操作与实验矩阵

应用可独立选择人脸切分方式和语音识别位置。默认语音模式为`电脑端中英`：FunASR 负责中英混合最终识别，断连时自动切回本地中英双模型 Vosk。Part A/C 本地条件选择`本地中英`；`本地中文`、`本地英文`用于单模型对照。语音选择在下一次开始采集时生效。

| 实验 | 人脸选项 | 语音选项 |
| --- | --- | --- |
| A 全本地 | 本地 | 本地中英 |
| B 人脸对齐后卸载 | 对齐后卸载 | 本地中英 |
| C 人脸整帧卸载 | 整帧卸载 | 本地中英 |
| D 语音卸载 | 本地 | 电脑端中英 |
| E 人脸与语音卸载 | 整帧卸载 | 电脑端中英 |
| F 语音模块静态对照 | 本地 | 本地英文 Vosk / 电脑端中英 FunASR，同一份英文 WAV |

各条件采用相同输入和重复次数。手机与电脑使用的语音模型不同，比较时需同时报告识别准确率。人脸 CSV 的上下行字节只计人脸请求，不包括语音 WebSocket 和网络探测；语音回放记录应用层发送/接收字节、首字延迟、完整时延、识别文字和电池读数。混说测试使用电脑端 FunASR 与手机中英双模型分别运行；手机端按词级置信度、语言特征和文本/时长比例选取候选，并以相同输入比较字幕质量。

1. 启动服务，在应用的“计算切分实验”选择模式、输入最大边长、上行限速与电脑地址。
2. 点击“运行样例切分实验”：自动使用仓库内的样例人脸，覆盖 320/640 像素、无上行限速/512 kbps、三个静态方案及动态方案，写入人脸 MEC CSV。打开“可复现实验素材”，还可对同一 60 秒英语 WAV 执行本地中英默认模式（20 秒样本）、本地英文 Vosk 与电脑 FunASR 的静态语音对照。
3. 真实视频实验需先获得参与者同意，固定设备、光照、人数和使用时间，分别运行三种静态方案，再运行动态方案；改变尺寸、限速或真实 Wi-Fi/蜂窝连接时记录环境。每种条件重复采样，排除启动预热帧，并分别记录 0/1/2 人等输入规模。
4. 点击“导出实验 CSV”，用系统文件选择器保存；运行 `py -3.12 server\summarize.py 路径\mec-experiments.csv` 生成分组表。原始 CSV 与设备型号、系统、网络、供电情况一起保存。
5. 动态实验改变上行限速或网络，观察界面实际执行位置与 CSV，统计适应前后的耗时。限速选项只控制本应用 HTTP 请求的上行发送速率；真实网络需要另行测量和标注。

## 动态决策

动态模式先分别采样三种方案，再比较指数滑动平均估计：`手机计算耗时 × CPU负载修正 + 电脑计算耗时 + RTT + 上传字节/上行速率 + 下载字节/下行速率`。网络由 64 KiB 上下行探针和一次健康请求每 15 秒测量；手机进程 CPU 时间与经过的时间估算负载。预估更优超过 15% 时切换，每 30 帧重新采样以更新剖析。设置改变后重新采样；动态模式连接电脑失败时回到本地执行。

## 测量解释

- `frame_to_track_ms`：摄像头帧进入分析到身份跟踪完成的时间，包含图像转换、排队、网络探测与计算；样例实验从样例处理开始计时。
- `pipeline_ms`：选择模式后到取得人脸特征的时间；`request_ms` 包含请求、网络和电脑计算，`remote_ms` 是电脑检测/对齐/提取合计，二者存在包含关系。
- `process_cpu_cores`：整个 Android 进程在两次取样之间消耗的 CPU 时间除以经过时间，1.0 约为一个逻辑核运行；包含并行语音和嘴部分析。
- `battery_current_ua`、`battery_charge_uah`、`battery_voltage_mv` 和 `battery_energy_nwh` 为 Android BatteryManager 原始读数；整数最小值表示设备不提供对应指标。电量计可用时，取相同采样区间首末 `battery_energy_nwh` 之差计算能耗；记录电池状态，使用实体机或外部电表，并明确测量区间与单位。
- 初次模型加载、缓存、电脑性能、帧内容与并行负载均会影响结果；报告中保留原始采样与实验条件，以中位数及分位数呈现结果。

## 可复现边界场景与语音切分

`testdata/reproducible-video/README.md` 记录公开来源、固定变换和 SHA-256。应用内置同一组回放文件，无需临时下载或现场录制：

| 场景 | 测试步骤 | 观察字段 |
| --- | --- | --- |
| 正常单人/英语 | 60 秒 Obama 英语片段；同一 PCM 分别送入英文 Vosk 和电脑 FunASR | ASR 文本、首字/总时延、上传/下载字节 |
| 双人同步发言 | Ilves 与 Obama 两段讲话的音视频对齐混合；20 秒 mono PCM 上传到电脑端 SepFormer | 分离耗时、设备、两路独立 FunASR 文本、两路字节、身份标签 |
| 人脸遮挡 | 固定视频在 5–10 秒遮挡两个脸部区域，按 2/4/6/8/10/12/15/19 秒检测 | 人脸数、轨迹 ID、遮挡前后轨迹恢复 |
| 人物出画与重入 | 横向平移摄像窗口，两人于 4–6 秒离开画面并于 10 秒前重入 | 人脸数、出画时标签消失、重入轨迹 ID |

双人实时重叠触发条件是同一个 ASR 发声窗口内至少两条嘴部活动轨迹时间重合；该窗口音频交给 SepFormer 分离，两个 FunASR WebSocket 请求并发转写。手机端先比较已登记声纹，再用分离音频 200 ms RMS 包络与嘴部活动序列做相关性匹配；证据不足时分配独立陌生人编号。短遮挡使用 8 秒跟踪保留窗，画面离开后立即停止绘制人脸框，保留期间重入沿用轨迹身份。

模拟器本机服务地址分别为 `http://10.0.2.2:8000`、`ws://localhost:10095`（需 `adb reverse tcp:10095 tcp:10095`）、`http://10.0.2.2:8001/separate-and-transcribe`。实体手机和电脑同一 Wi-Fi 时，在 App 中填入电脑局域网 IPv4。通过“导出复现实验 CSV”保留 Part B/C 及语音级结果，通过“导出边界场景诊断 CSV”保留 Landmarker 匹配数、逐轨嘴部样本和重叠轨迹。双人重叠条件以两路字幕均非空、该次请求汇总的上传/下载字节大于 0、身份标签分别关联到登记身份或陌生人编号为验收项；脸部遮挡和出画条件核对检测数下降与轨迹重入。
