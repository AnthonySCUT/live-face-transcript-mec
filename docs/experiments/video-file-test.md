# 使用固定视频进行人脸与语音测试

主界面新增“导入视频测试（使用当前人脸与语音设置）”。选择带声音的视频文件后，程序从文件读取画面与音轨，不启用摄像头、麦克风或扬声器，也不需要它们的权限。

## 操作

1. 安装本分支构建的 APK。将参与者同意用于实验的测试视频复制到安卓设备“下载”目录。
2. 停止实时采集。设置人脸模式、输入最大边长、电脑服务地址、上行限速和语音模式，再勾选参与者同意。
3. 点击“导入视频测试”，在系统文件选择器中选择视频。建议先用 10 秒左右的 MP4（H.264 视频、AAC 音频）检查设备解码兼容性。没有音轨的文件会报错；暂不提供单独音频文件入口。
4. 等待处理结束，点击“导出本次结果 ZIP”。要中途结束可点击“停止测试”；切到后台或离开页面也会取消，已完成记录保留。回到主界面可重新选择同一视频，运行下一组。
5. 五组设置见下表。使用同一视频、设备和参数重复测试，不要把动态模式混入静态组。

| 组别 | 人脸模式 | 语音模式 |
| --- | --- | --- |
| 全本地 | 本地 | 本地中文或本地英文 |
| 对齐后卸载 | 对齐后卸载 | 与全本地相同 |
| 整帧卸载 | 整帧卸载 | 与全本地相同 |
| 仅语音卸载 | 本地 | 电脑端中英 |
| 均卸载 | 整帧卸载 | 电脑端中英 |

本地英文需先在主界面导入英文模型；电脑端中英需配置可访问的 FunASR。人脸卸载需电脑人脸服务。本版本文件测试不启用声纹录入/匹配，以免实验样本污染身份声纹库。字幕使用原有已登记人脸与嘴部归属规则。

## 执行与数据解释

- 每 200ms 采样一个视频帧（5 FPS），音轨由 Android MediaExtractor/MediaCodec 解码为 PCM，混合声道并以线性插值转换到 16 kHz 单声道。推荐统一准备 16 kHz 单声道音轨以减少重采样差异。
- 以媒体时间排序并限速到约 1 倍速；处理性能不足时会落后视频时间、总时间变长，不主动丢弃采样帧。这是可重复文件输入测试，不等同于 CameraX 的实时丢帧策略，也不是尽可能快的离线批处理。
- 文件结束时刷新 Vosk 未结束的最后一句；FunASR 沿用现有 750ms 结束等待窗口。较慢的远端最终结果仍可能未收到，应检查实际字幕记录，不把正常结束视为远端识别完整性证明。
- 视频测试不向正式转写历史写入记录，也不追加到实时人脸 `mec-experiments.csv`。每次运行生成独立目录和 ZIP：
  - `summary.txt`：源文件名、设置、结束状态、帧数和总墙钟时间（包括模型加载）。
  - `frames.csv`：视频时间、实际处理时间、实际人脸切分方案、输入尺寸、人脸阶段耗时、人脸请求字节数和人数。
  - `transcripts.csv`：临时/最终字幕、音频媒体时间、结果收到时的墙钟时间、说话人。统计最终文本时只选 `final=true`。
- 文件不会复制进仓库或打包进结果，导出仅包含文本数据。相同文件名不保证内容相同，正式实验请另行记录源文件哈希。
- 人脸字节数仍不包含语音 WebSocket、探测流量或整机流量。媒体时间是声音窗口，不是字词级准确标注；最终字幕时间也不是经过校准的人工首字延迟。CPU、能耗和准确率实验仍需单独采集。

## 验证范围

单元测试覆盖 PCM 通道混合/重采样、跨块连续性以及音轨结束时的最后一句刷新；APK 构建不能证明手机视频解码与实际识别已正常。本云环境未连接 Android 设备，以下必须在目标手机/模拟器验收：带音轨 MP4、无音轨/损坏文件报错、英文与中文识别、远端识别、停止/后台取消、导出 ZIP、三种静态人脸模式及嘴部字幕归属。
