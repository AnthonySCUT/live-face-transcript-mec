## 一、项目简介

本项目开发一款 Android 实时人脸识别与中英语音转录 App，并以手机作为移动端、开发电脑作为边缘服务器，研究不同执行位置对端到端响应时间、网络传输和设备负载的影响。

应用持续采集视频帧与麦克风音频。人脸流水线支持手机本地执行、手机完成检测和对齐后将人脸小图交给电脑提取特征，以及把整帧交给电脑执行人脸处理。动态模式根据实际测得的计算时间、网络带宽、往返时延和手机负载选择执行方案。嘴部运动分析和语音转写按照当前工程配置独立运行。

## 三、当前功能

### 3.1 实时视频与身份识别

- CameraX 从 Android 模拟器或实体手机持续获取摄像头帧。
- OpenCV YuNet 负责多人脸检测，SFace 负责对齐和人脸特征提取。
- 应用将本机提取的特征与 SQLite 中的登记特征比较，在画面显示已登记姓名或本次会话中的陌生人编号。
- MediaPipe Face Landmarker 分析嘴部开合变化；语音转录的说话人归属依据语音时间附近的嘴部运动证据确定。
- 用户可登记、管理身份，并查看本机保存的转写文本、时间和说话人标签。

### 3.2 实时语音转录

- Android `AudioRecord` 采集 16 kHz 单声道音频。
- FunASR WebSocket 服务提供中英混合流式转写，临时结果可实时显示，最终结果保存到本机。
- FunASR 不可用时，应用切换到本机 Vosk 中文识别。
- 多人画面中的说话人归属通过嘴部可见运动估计，并与转写时序对齐。

### 3.3 MEC 固定切分与动态模式

界面可选本地、对齐后卸载、整帧卸载和动态模式；可设置输入尺寸、电脑服务地址及上行模拟限速。样例实验读取仓库内的测试人脸，生成包含切分位置、时延、字节数、CPU 和电池状态的 CSV，可直接通过系统文件选择器导出。

## 四、模块结构与端云数据流

### 4.1 人脸处理主流水线

```text
Android 摄像头
    │ 视频帧
    ▼
格式转换、旋转与缩放（手机）
    │
    ├── 本地模式：YuNet 检测 → SFace 对齐 → SFace 特征提取（手机）
    │
    ├── 对齐后卸载：YuNet 检测 → SFace 对齐（手机）
    │                                  │ 112×112 人脸 PNG
    │                                  ▼
    │                       电脑 SFace 特征提取
    │
    └── 整帧卸载：JPEG 视频帧 ────────> 电脑 YuNet 检测
                                            → SFace 对齐
                                            → SFace 特征提取
                                                   │ 128 维特征
                                                   ▼
手机身份库余弦匹配 → FaceTracker 跟踪和陌生人编号 → 人脸标签显示
```

### 4.2 并行嘴部与语音流程

```text
视频帧 → MediaPipe Face Landmarker → 嘴部活动时间序列 ─┐
                                                       ├→ SpeakerAttributor
麦克风 PCM → FunASR 实时转写 → 文本及时间戳 ────────────┘
                                  → Vosk 中文后备
                                  → 本机转写历史
```

### 4.3 三种固定执行位置

| 方案 | 手机执行 | 电脑执行 | 传输内容 |
| --- | --- | --- | --- |
| 本地 | 检测、对齐、特征提取、身份匹配、跟踪 | 无 | 无人脸推理请求 |
| 对齐后卸载 | 检测、对齐、身份匹配、跟踪 | 特征提取 | 对齐人脸 PNG 与边界框 |
| 整帧卸载 | 采集、身份匹配、跟踪 | 检测、对齐、特征提取 | JPEG 整帧 |

每个请求返回人脸边界框和 128 维特征，身份匹配及个人身份库保留在手机端。实际上传大小依帧内容、检测到的人数和压缩结果而变化，实验以记录的传输字节数为准。

## 五、动态切分组件设计

电脑推理服务运行在本机 `8000` 端口。Android 模拟器通过 `10.0.2.2` 访问开发电脑；实体手机使用电脑的局域网地址访问。动态模式维护三个切分方案的指数滑动平均性能剖析，并定期测量 64 KiB 上下行探针与 HTTP 往返时延。

候选方案时延估算为：

```text
预计总时延 = 手机计算耗时 × 当前负载修正
           + 电脑计算耗时
           + 网络往返时延
           + 上传字节数 / 实测上行速率
           + 下载字节数 / 实测下行速率
```

手机进程 CPU 时间与采样间隔用于估计手机负载。当新方案预计至少快 15% 时切换；每 30 帧重新采样候选方案。网络测量约每 15 秒更新。动态模式连接电脑失败时在手机本地执行，切分记录保留在 CSV 中。

## 六、实验设计与数据计划

### 6.1 自变量

| 自变量 | 建议水平 |
| --- | --- |
| 执行方案 | 本地、对齐后卸载、整帧卸载、动态 |
| 输入尺寸 | 320、480、640 像素最大边长 |
| 上行网络 | 不限速、512 kbps、2 Mbps、10 Mbps；另记录真实 Wi-Fi 或蜂窝网络 |
| 人脸数量 | 0、1、2 人；逐步增加至应用可稳定处理的人数 |
| 手机负载 | 空闲、摄像头与嘴部分析运行、语音转录并行运行 |

### 6.2 采集指标

- 端到端帧处理到身份跟踪时延，以及中位数和 P95。
- YuNet 检测、SFace 对齐、特征提取、手机到电脑请求分别耗时。
- 每帧上传与下载字节数、探测带宽和网络往返时延。
- Android 进程 CPU 使用量，以及 BatteryManager 可用的电流、电量、电压、能量读数。
- 实际执行的切分位置和网络变化后的切换时刻。

模拟限速用于控制变量，真实 Wi-Fi/蜂窝环境需要另外记录网络类型与测量值。能耗结论以提供可靠读数的实体机或外部电量测量设备为准，并注明采样区间和测量方法。

### 6.3 建议实验步骤

1. 固定手机、电脑、电源状态、光照、相机距离和输入样本，预热模型后开始记录。
2. 分别运行三种静态方案，并按相同输入尺寸、网络条件和人脸数量采样。
3. 每个实验条件重复多轮，保存原始 CSV 与设备、系统、网络信息。
4. 运行动态模式，分阶段改变限速或网络环境，对比切换前后的时延和执行位置。
5. 使用 `server/summarize.py` 按模式、尺寸和限速汇总中位数及 P95，并据此制作报告图表。

电脑服务安装和完整命令见 [端云实验指南](../experiments/mec-partitioning.md)。
